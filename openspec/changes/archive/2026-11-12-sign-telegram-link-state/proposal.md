## Why

`GET /telegram/callback` is public (no authorizer). `handleLinkCallback` calls `store.consumeState(sha256(state))` for any request that carries `code` and `state`, so a request with random values still makes a Data API call and resumes the paused Aurora cluster. Cheap forged requests should be rejected at the edge, before any database, Cognito or Telegram call.

## What Changes

- `state` becomes a signed, expiring token: `base64url(payload) + "." + base64url(HMAC-SHA256(secret, payload))`. Payload = random nonce plus expiry (epoch seconds, `LINK_REQUEST_TTL_MS` after issue). About 70 characters.
- New random secret `bot-link-state-secret` (Pulumi `RandomPassword` + Secrets Manager, same pattern as `bot-webhook-secret`). Read by the worker (signs) and the callback (verifies), cached with `getSecretString`.
- Callback order: (1) `error` or missing params → `FAILED_PAGE`; (2) malformed state, bad signature (constant-time compare) or expired → `EXPIRED_PAGE` with no database, Cognito or Telegram call; (3) only then `consumeState`, still single-use via the stored `sha256` of the full state string.
- No database migration: the stored value is still `sha256(state)`.
- Requests issued before the deploy (old-format state) fail with `EXPIRED_PAGE`. Accepted: links last 10 minutes.
- Docs: `docs/telegram-bot.md`, `docs/architecture.md`.

Non-goals: the 6-digit code flow, the Cognito client, PKCE.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `telegram-account-linking`: the link's state value is a signed, expiring token, and an invalid or expired one is refused without any database, Cognito or Telegram call.

- `bot/src/lib/linking/state.ts` (new), `callback.ts`, `unlinked.ts`, `config.ts` (unchanged unless TTL helper needed), `bot/src/callback.ts`, `bot/src/worker.ts`, `bot/src/lib/linking/linking.spec.ts`
- `infra/lib/bot.ts` (secret, IAM read for worker and callback, env var `LINK_STATE_SECRET_ARN`)
- `docs/telegram-bot.md`, `docs/architecture.md`
- `openspec/specs/telegram-account-linking` (delta)
- Deploy: no manual step; the secret is generated by Pulumi. Worker and callback must deploy together (one `infra:up`).
